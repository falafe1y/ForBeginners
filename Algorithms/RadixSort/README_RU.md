## Теория
**Big O** — O(n * k), где `n` - количество элементов, `k` - количество разрядов в максимальном числе

**Radix Sort** — это алгоритм, который сортирует числа, начиная с младших разрядов (единиц) и заканчивая старшими (десятками, сотнями и т.д.). Для каждой итерации используется вспомогательная сортировка по текущему разряду (например, Counting Sort).

Алгоритм стабилен, так как сохраняет порядок одинаковых чисел из исходного массива.

### Плюсы

- Линейное время работы для ограниченного диапазона
- Если числа имеют ограниченную длину (количество разрядов), алгоритм работает за O(n⋅k)O(n⋅k), где nn — размер массива, а kk — число разрядов. Это быстрее, чем O(nlog⁡n)O(nlogn) у таких алгоритмов, как Merge Sort или Quick Sort, для больших nn.

- Отсутствие рекурсии
- Алгоритм прост для реализации, так как не использует рекурсивных вызовов (в отличие от Quick Sort и Merge Sort).

- Стабильность сортировки
- Radix Sort сохраняет порядок элементов с одинаковыми значениями. Это полезно для задач, где элементы имеют дополнительные ключи, помимо чисел.

- Отсутствие сложных операций
- Алгоритм опирается только на разбиение по цифрам и сортировку подсчетом, что делает его понятным и предсказуемым.

### Минусы

- Зависимость от диапазона значений
- Если числа имеют большое количество разрядов (например, 20-значные числа), алгоритм становится менее эффективным, так как число итераций растет. При этом, если значения разряда распределены неравномерно, подсчет может стать неэффективным.
- Ограничение на типы данных
- Алгоритм лучше всего работает для целых чисел. Для вещественных чисел или строк его реализация усложняется.
- Затраты памяти
- Для каждого разряда создается дополнительный массив, что увеличивает требования к памяти. Это может быть проблемой для больших массивов.
- Неприменимость для всех типов данных
- Radix Sort трудно использовать для сортировки сложных объектов, где порядок определяется не только числами.
- Неэффективность для небольших массивов
- Для небольших массивов n⋅kn⋅k может быть больше, чем nlog⁡nnlogn, из-за накладных расходов.
# Объяснение
```cpp
void countingSortByDigit(std::vector<int>& arr, int exp) {

    if (arr.empty()) return;

    int arr_size = arr.size();
    std::vector<int> sorted(arr_size); // Array for sorted elements
    int count[10] = {0};       // Array for values form 0 to 9

    // Count the number of elements for each value of the current digit
    for (int i = 0; i < arr_size; i++) {
        int digit = (arr[i] / exp) % 10; // Extract the current digit
        count[digit]++;
    }

    // Modify count[i] so that it contains the index to place the number
    for (int i = 1; i < 10; i++) {
        count[i] += count[i - 1];
    }

    // Sort by current rank (go from the end for stability)
    for (int i = arr_size - 1; i >= 0; i--) {
        int digit = (arr[i] / exp) % 10;
        sorted[count[digit] - 1] = arr[i];
        count[digit]--;
    }

    // copy sorted array back to source
    for (int i = 0; i < arr_size; i++) {
        arr[i] = sorted[i];
    }
}

// Main Radix sort function
void radixSort(std::vector<int>& arr) {
    // Find the maximum number to determine the number of digits
    int maxVal = *std::max_element(arr.begin(), arr.end());

    // Sort by each digit, starting with ones
    for (int exp = 1; maxVal / exp > 0; exp *= 10) {
        countingSortByDigit(arr, exp);
    }
}
```

**Функция countingSortByDigit (вспомогательная сортировка подсчетом):**

Извлекает текущий разряд числа (`digit=(arr[i]/exp)%10digit=(arr[i]/exp)%10`). Далее считает, сколько раз каждый возможный разряд (0…9) встречается в массиве, сохраняя эти данные в массиве `count`, а после преобразует массив `count` так, чтобы он содержал индексы, где элементы должны находиться в отсортированном массиве. После сортирует элементы по текущему разряду, начиная с конца массива для сохранения стабильности сортировки. В конце копирует отсортированный массив обратно в оригинальный массив.

**Функция radixSort:**

Находит максимальное число в массиве, чтобы определить количество разрядов для сортировки, после поочередно вызывает `countingSortByDigit` для каждого разряда числа (1 — единицы, 10 — десятки, 100 — сотни и т.д.). В результате массив оказывается отсортированным по возрастанию.

### Пример

Исходный массив:
`[329, 457, 657, 839, 436, 720, 355]`

1. Шаг 1: Сортировка по единицам (`exp = 1`)

    - Извлекаем последние цифры: [9, 7, 7, 9, 6, 0, 5]
    - Сортируем по этим цифрам: [720, 355, 436, 657, 329, 839, 457]

    Массив после первой итерации:
    [720, 355, 436, 657, 329, 839, 457]
2. Шаг 2: Сортировка по десяткам (`exp = 10`)

    - Извлекаем цифры десятков: [2, 5, 3, 5, 2, 3, 5]
    - Сортируем по этим цифрам: [720, 329, 839, 436, 355, 457, 657]

    Массив после второй итерации:
    [720, 329, 839, 436, 355, 457, 657]
3. Шаг 3: Сортировка по сотням (`exp = 100`)

    - Извлекаем цифры сотен: [7, 3, 8, 4, 3, 4, 6]
    - Сортируем по этим цифрам: [329, 355, 436, 457, 657, 720, 839]

    Массив после третьей итерации:
    [329, 355, 436, 457, 657, 720, 839]

Итог:

Отсортированный массив:
`[329, 355, 436, 457, 657, 720, 839]`
