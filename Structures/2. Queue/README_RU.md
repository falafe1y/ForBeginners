# Очередь
- [ ] Закончено?
## Теория

Очередь (Queue) — это структура данных, работающая по принципу FIFO (First In, First Out — первый пришел, первый ушел). Это означает, что элементы в очереди добавляются в конец (в заднюю часть очереди) и извлекаются из начала (передней части очереди).

Примером послужит обычная очередь в магазине: придя в первым вы также первым и дождетесь обслуживания и ухода из магазина (очереди).

Можете также представлять себе автомобильный конвеер: авто, которое первым поставили на ленту, первым с ленты и уйдет. Надеюсь принцип работы ясен.

**Где используется?**:

- Ожидающие процессы в операционных системах(Scheduling);

- Алгоритмы обработки данных, где элементы обрабатываются в порядке их поступления, например поиск в ширину (BFS);

- Программирование с многозадачностью и многопоточностью. Например, producer-consumer паттерн;

- Буферизация данных;

- Обработка событий;

- Сетевые приложения (управление потоками данных);

# Объяснение
**Методы**:

- enqueue - добавление элемента в конец очереди
- dequeue - удаление элемента из начала очереди
- peek - возвращает первый элемент без удаления
- getSize - возвращает размер очереди
- getCapacity - возвращает значение `вмещаемости`, на какое количество элементов в целом рассчитан конкретный объект класса
- getQueue - возвращает все элементы очереди
- isEmpty - проверка на пустую очередь
- isFull - заполнена ли очередь до конца
___

```cpp
class Queue {
private:
    int* data;       // Array for storing elements
    int capacity;    // Queue capacity
    int front;       // Queue start index
    int rear;        // Queue end index
    int size;        // Current size of queue
```
Моя реализация очереди основана на массиве, а не на связном списке, как у многих. Вот плюсы и минусы такого решения:

|Характеристика|Очередь на основе массива|Очередь на основе связного списка|
|---|---|---|
|**Производительность (вставка/удаление)**|O(1) (если не требуется перераспределение)|O(1) (при наличии указателей на начало/конец)|
|**Память**|Эффективное использование памяти|Требует дополнительной памяти для указателей|
|**Размер**|Ограничен заранее заданной емкостью|Динамическая память, может расти по мере необходимости|
|**Управление памятью**|Проблемы с перераспределением|Динамическое выделение памяти|
|**Гибкость**|Ограниченная гибкость (фиксированная емкость)|Высокая гибкость (динамическое изменение размера)|
|**Кэширование**|Отличная локальность данных|Плохая локальность данных|
|**Сложность реализации**|Простая|Сложная, требует работы с указателями|

И все же первопричина такого решения в том, что связные списки по определению сложнее очереди. Чтобы создать очередь на основе связного списка **необходимо понимать устройство связного списка**, а мы не прошли и очереди. Я считаю это малость нелогичным.
___
```cpp
// Add element in queue
void Queue::enqueue(int value) {
    if (isFull()) {
        return;
    }
    rear = (rear + 1) % capacity;
    data[rear] = value;
    ++size;
}
```
`rear + 1` — увеличивает текущий индекс `rear` на 1. Это означает, что мы пытаемся переместиться к следующей ячейке в массиве. `% capacity` — оператор остатка от деления (модуль). Он гарантирует, что индекс не выйдет за пределы массива. Если `rear + 1` становится равным `capacity` (то есть выходом за пределы массива), то вместо выхода за границы массива результат выражения будет равен 0 (началу массива). 

То есть **при достижении конца массива индексы будут "оборачиваться" обратно к началу**.
### Пример:

Предположим, что `capacity` равна 5, а текущий индекс `rear` равен 4. Тогда:

- Увеличиваем `rear` на 1: `rear + 1 = 5`.

- Берем остаток от деления на `capacity` (получаем 5 % 5): результат равен 0.

Таким образом, после выполнения этой строки значение `rear` будет равно 0, что означает, что **следующий элемент будет добавлен в начало массива**.

Далее берем массив `data`, находим у него индекс `rare`, который мы только что высчитали, и присваиваем этому элементу массива значение `value`.
___
```cpp
// Delete element from queue
int Queue::dequeue() {
    if (isEmpty()) {
        throw invalid_argument("The queue is empty!");
    }
    int value = data[front];
    front = (front + 1) % capacity;
    --size;
    return value;
}
```
Если быть точным, то мы *не удаляем* элемент, а просто сдвигаем рабочую с очередью область вправо. Наглядно это продемонстрированно в `main.cpp`:

- Изначально очередь выглядит так - `[10 20 30 40]` 
- Далее мы удаляем первый элемент - `Deleted: 10`
- Опять выводим очередь и видим странное - `[10 20 30 40]`. 

Да, очередь осталась нетронута, но ведь front сдвинулся на одну позицию вправо, а об этом мы забыли. 

Еще более наглядный пример: `f` - front, `r` - rear

- Изначальная очередь:

```cpp
                                [10 20 30 40]
                                 f        r                               
```

- Удаляем первый элемент - `Deleted: 10`
- Полученная очередь:

```cpp
                                [10 20 30 40]
                                    f     r                               
```
___
```cpp
vector<int> Queue::getQueue() const{
    vector<int> returnData = {};
    for (int i = 0; i < capacity; ++i) {
        returnData.push_back(data[i]);
    }
    return returnData;
}
```

Как правило никто не пишет такой метод, но мне показалось будет полезным увидеть работу очереди в деле. Так как сам по себе указатель на массив `*data` из фукнкции передать нельзя, внутри функции создается вектор `returnData`, который будет хранить итоговый массив доя передачи. Далее простым циклом от 0 до `capacity`, (т.е. до значения вместимости очереди) перебирается каждый элемент вектора returnData с последующим присвоением соответствующих элементов из `*data`.
___
```cpp
// Is the element contained in the queue
bool Queue::contains(int value) const {
    for (int i = 0; i < size; ++i) {
        int index = (front + i) % capacity;
        if (data[index] == value) return true;
    }
    return false;
}
```

Перебираем каждый элемент от 0 до `size`. Строку `int index = (front + i) % capacity;` мы уже рассматривали в методе `enqueue`. Далее простая проверка - если элемент очереди по текущему индексу совпадает с переданным значением, то возвращаем `true`, иначе `false`. Имеем *O(n)*.
